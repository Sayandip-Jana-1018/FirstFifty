# ADR-0004: Monorepo with pnpm + Turborepo, and Gradle for the backend

- Status: Accepted
- Date: 2026-11-24
- Deciders: Sayandip, Claude

## Context
The API, web app, mobile app, extension, design tokens and generated API client change together. Keeping them in sync across separate repos causes drift and broken clients.

## Decision
One private GitHub repo. pnpm workspaces + Turborepo for the TypeScript projects (`apps/web`, `apps/mobile`, `apps/extension`, `packages/*`); the Gradle wrapper (Kotlin DSL) for `services/api`. The OpenAPI spec generated by the backend feeds `packages/api-client`.

## Consequences
- Atomic changes across API and clients; one CI.
- CI needs path filters and caching to stay fast.
- Expo inside a pnpm monorepo needs the right Metro and linker settings: follow Expo's current monorepo guide when scaffolding.

## Alternatives considered
- **Separate repos:** synchronisation pain.
- **Nx:** more features than we need, and heavier.

## Revisit when
CI regularly takes over 15 minutes despite caching.
